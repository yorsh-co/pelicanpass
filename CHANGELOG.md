# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

The public history of this project starts at 2.0.0. Earlier versions, up to 1.2.0, were developed in a private repository and are not published.

## [Unreleased]

### Added

- `docs/images/banner.svg`, the primary wordmark on a Harbour rounded rectangle, generated by `npm run brand:build` and shown at the top of `README.md`
- `npm run build:demo` and `scripts/demo/`, a static build of the app for Cloudflare Pages: the view fixtures rendered through the production CSP with hashes in place of nonces, the pre-event countdown at `/landing`, a banner with the demo ticket codes and links to `/staff` and `/admin`, in the page's language, `_headers`, `_redirects`, `robots.txt` and `X-Robots-Tag: noindex`, written to `dist/demo/`
- `src/web/client/demo/`, an in-browser mock of the attendee, staff and raffle API over a fictional roster, kept per tab in `sessionStorage` and bundled only by the demo build; the admin screens are read-only and show a notice for every mutation
- A build test that fails when a demo bundle calls an `/api/v1` path with no mock handler or explicit refusal
- `docs/operations/demo-site.md`, the runbook for building, rehearsing and deploying the demo, and a link to the live demo in `README.md`
- `npm run docs:screenshots` and `scripts/docs/screenshots.ts`, which capture eleven screens of the static demo with `playwright-core` into `docs/images/screenshots/`, shown in `README.md`
- `assets/images/logo/mark.svg`, the mark alone with no ground, and `assets/images/logo/wordmark-two-tone.svg`, the lettering alone in white and Shallows, both generated by `npm run brand:build`
- `en`, published: English is served in production, offered by the language switcher and selected by `Accept-Language`, with every message catalog and both questionnaires translated, and courtesy translations of the privacy notice and the terms of use, in which the pt-BR text is authoritative

### Changed

- The footer credits Yorsh, linking to the repository, from a fixed `CREDIT` constant (`src/constants/credit.ts`) rather than `COPY_DEFAULTS`, so a per-event copy setting cannot replace the authorship credit; the copyright line still names the event
- `npm run docs:screenshots` captures every screen in each demo locale, into `docs/images/screenshots/en/` and `docs/images/screenshots/pt-BR/`; `README.md` shows the English ones
- The language switcher labels English `EN` rather than `US`: it shows the locale's own region, or its language when it names none
- The demo serves every page in pt-BR and in English, the English copies under `/en/`, switched by the footer, the admin menu or the banner; the choice is kept per visitor in `localStorage`, and a first visit follows the browser language. A script at the top of every page sends the visitor to the matching tree, including from the app's own root-absolute links, and `_redirects` is mirrored under `/en`; the banner is written in the page's language only
- `scripts/static/build.ts` hashes only the inline scripts a browser executes: `type="application/json"` data blocks are data, so the demo's policy shrinks from 1,607 to 419 characters, well inside the 2,000 Cloudflare allows in a header value, and the demo build fails if it grows past that
- The demo banner collapses to one line, with a Details button that expands it; it starts collapsed on viewports up to 40rem wide and saves the visitor's choice in `localStorage`
- The volunteer pass shows its tier as a chip with a chevron, in place of the tab, plus a tier-coloured edge along the card's top; the five tier colours are one family at a shared lightness and chroma beside Harbour, and the actions face keeps the brand backdrop
- The boot screen shows the mark at the centre of the viewport with the two-tone wordmark pinned to the bottom, replacing the one-line lockup and the three star and ring motifs; the landing and closing pages open on the same mark and wordmark so the hand-off between them reads as one surface
- The view fixtures live in `src/web/views/fixtures.ts` and the helmet CSP directives in `src/config/csp.ts`, shared by the app, the snapshot suite and the static builds; `scripts/static/` exports its header and asset helpers
- The mark is optically centred on its grid, at x 52 rather than its bounding-box centre at 57, so it no longer reads as sitting left; every icon, the favicon and the README banner are regenerated

### Removed

- `docs/development/static-demo-plan.md`, the implemented plan for the static demo; its design decisions are now in `docs/operations/demo-site.md`
- `docs/development/english-locale-plan.md`, the implemented plan for the `en` locale; its glossary is now the "English terminology" section of `docs/development/copy-management.md`, and its design decisions are in that document and `docs/operations/demo-site.md`
- `src/web/client/demo/banner-language.ts`, its test and its `localStorage` key, replaced by the demo's page-level language choice
- The `star-sm.svg` and `star-with-discs.svg` motifs, `scripts/brand/motifs.ts` and the motifs section of `docs/design/brand.md`

### Fixed

- The pass shows the check-in moment with an abbreviated month in English, and every time on the pass in 24-hour format, so the footer line no longer wraps on the volunteer pass
- `npm run docs:screenshots` captured the check-in ticket step before its hint was shown, so `checkin-ticket.png` changed from run to run; both check-in captures now wait for the hint to finish fading in
- `npm run docs:screenshots` drew the rotation window's ring at whatever level it had drained to by the time of the capture, so `pass-back.png` and `staff.png` changed from run to run; the ring is now held at three quarters
- `npm run docs:screenshots` could capture a page before its delayed animations ran, so the footer, which fades in 0.4s after load, was missing from some screenshots and present in others; every capture now waits for running animations to finish
- The `admin-redemptions-index` view fixture gave the item's share as `50` instead of a 0-1 ratio and carried no counts, so the snapshot and the static demo showed "5.000% retirado" and blank figures; it now has the counts and a per-option breakdown
- The demo banner took the admin shell's rail column, so on wide screens the navigation sat in the content column and the screen below it; it now spans the whole row above both
- The 17/10 event report gave the participant meal and drink window as 17:45-18:29; the check-in export puts it at 17:55-18:18, a span of 23 minutes

## [2.0.0] - 2026-10-20

### Added

- `COPY_DEFAULTS` in `src/constants/copy-defaults.ts`, the event name, organiser name and organiser URL filled into the copy, carrying the PelicanPass brand
- `{name}` placeholders in the Markdown content files (notices and questionnaires), filled from `COPY_DEFAULTS` by `src/shared/utils/copy-placeholders.ts`; an unknown placeholder fails the boot, and square-bracket operator fields are left alone
- `--host-church <name>` option for the post-event report build, naming the church that hosts the event
- `docs/design/brand.md`, the PelicanPass brand guide: the mark's construction, the wordmarks, the colour palette with contrast ratios, the backdrop, the motifs, the type and the icon files
- `npm run brand:build` and `scripts/brand/`, a generator that draws the PelicanPass icons, wordmarks, backdrop and motifs from the brand guide
- Implementation plans for the admin result exports, the admin CSV import and a faster QR scanner, in `docs/development/` and linked from the roadmap

### Changed

- The icons, wordmarks, backdrop and boot-screen motifs are the PelicanPass identity from `docs/design/brand.md`, and `--text-on-brand-muted` is Shallows (`#cfe6e8`)
- The accent is Harbour in the light theme and Pouch in the dark, replacing the previous magenta and teal across check-in, the pass, staff and admin; the questionnaire chip on the pass is Pouch with Abyss ink in both themes, and the neutral access tier and the landing page's `theme-color` follow the new backdrop
- The footer names the event and links the organiser from `COPY_DEFAULTS`, and the wordmark alt text and the header and admin rail `aria-label` read `chrome.wordmarkAlt`
- The check-in redirect and pass welcome lines no longer name the event, and the questionnaire card heading takes the event name from `COPY_DEFAULTS`
- The venue map is served as `/assets/images/map/venue-map.svg`, and is now a generic sample map with matching alt text
- The WhatsApp template descriptions use an example domain instead of the original event's
- The product name is spelled `PelicanPass` in the default `APP_TITLE`, in `.env.example` and in `README.md`
- `src/web/content/pt-BR/terms-of-use.md` and `privacy-notice.md` are templates: they open with a review banner for the operator and carry bracketed legal fields (`[RAZÃO SOCIAL]`, `[CNPJ]`, `[CONTATO]`, `[SITE]`) instead of the original organiser's identity
- The participant and volunteer questionnaires in `src/web/content/pt-BR` are replaced with short generic ones, and the report's rating groups in `scripts/report/core/rating-groups.ts` follow the new question ids
- Questionnaire ids are English snake_case (`overall_rating`, `would_return`) with the copy still in pt-BR, and the report links a follow-up text question to its parent as `<id>_comment`
- The post-event report's title, cover and slides take the event name from `COPY_DEFAULTS`
- The post-event report compares the host church with the other churches only when built with `--host-church`
- The post-event report stores its preferences under `pelicanpass-report-` keys; settings saved under the old keys are not carried over
- `CHANGELOG.md` starts at the public `2.0.0` release, with the entries for earlier versions left in the private history
- The documentation and the event report use neutral examples instead of the original event's names
- The production host is named `prod-server` (SSH aliases `prod-server-cf`, `prod-server-cf-standby`) in the docs, scripts, compose file and load-test history
- The development host is named `dev-server` in the docs, scripts and load-test history
- cloudflared 2026.10.2 (was 2026.10.0)
- Tailscale v1.104.1 (was v1.102.5)
- The dev server (`npm run dev:app`) restarts with `node --watch` instead of nodemon, and `nodemon.json` is gone. It restarts only for files the server imports, so edits to views and to `src/web/content/*.md` need a manual restart. Restarts send `SIGUSR2`, as nodemon did, so they skip the graceful shutdown and its "Application stopped cleanly" alert

### Removed

- The parent organisation's privacy policy document; `SECURITY.md` now names the operator of a deployment as its data controller

### Security

- Development dependencies refreshed in `package-lock.json` for four advisories: `shell-quote` 1.9.0 → 1.12.0 under `concurrently` 9.2.5 (GHSA-pqg4-j6r4-53mv), `brace-expansion` 5.0.9 → 5.0.12 (GHSA-q2hr-2g5m-vwhr, GHSA-qhr7-859c-m2p7, GHSA-6j4f-fj2g-mc7p) and `fast-copy` 4.0.3 → 4.2.0 (GHSA-jggr-w7fw-pc2j). None of them ships in the production image
- Removing nodemon drops `chokidar` 3 and `braces`, clearing GHSA-vfj7-8cjw-p6xm, which had no fixed release
- The post-event report loads ECharts 6.1.0 instead of 5.5.1 (GHSA-fgmj-fm8m-jvvx, an XSS in the default tooltip of the `lines` series); the report draws only bar and line series, so it was not exposed
